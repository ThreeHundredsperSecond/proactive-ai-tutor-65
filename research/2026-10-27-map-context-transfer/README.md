# Карта с входным состоянием и другим источником

Агентные применения сохранены 27 октября 2026; офлайн-анализ завершён 28 октября. **Контекст помог подтвердить вход одного известного применения дискриминанта и не превратил прежние действия в новые в двух контрольных случаях.** При одинаковых итоговых статусах без контекста остаются расхождения об основаниях. Второй источник дал два сопоставленных поддействия одной задачи; остальные пять трасс показывают пробелы маленькой карты.

Это ограниченная исследовательская проба, не готовая предметная карта, не внешняя экспертиза и не проверка освоения учеником. Результаты и замечания требуют просмотра пользователем; согласование не зафиксировано. Старые карты, каталоги, промпты и ответы сохранены без изменений. Новых решений ЕГЭ, платных API-запросов и дополнительных агентных применений при завершении анализа нет.

## Что выполнено

[Протокол до выполнения](PROTOCOL.md) задал семь агентных задач: редактуру восьми определений по фиксированным целям и официальному входу; извлечение шести первых записей из трёх заданных файлов старой репы; четыре применения трёх известных текущих шагов; одно применение карты к шести готовым трассам. Карточки заморожены перед применениями. Это уточнение по заданным целям, а не независимое обнаружение восьми KC. В сохранённых исходах есть все запланированные продукты; повторный запуск моделей не требовался.

Три контекстных случая взяты из сохранённого A19×3, r1: №16/s4 — дискриминант, №2/s3 — длина вектора против карточки скалярного произведения, №15/s2 — использование ОДЗ против карточки составления логарифмических ограничений. Для каждого случая передан либо только current, либо тот же current и буквальные результаты предшествующих шагов. В каждой ветви два изолированных применения, во втором порядок случаев обращён. Контекст разрешён как источник входного состояния, но не как свидетельство новой операции в current.

Второй источник — приватная репа `math_skills_ankli_obsidian` на commit `e5781a182c9e9d60430ea64b41a9cfa5149f22eb`. Взяты первые две записи каждого из заранее заданных файлов по логарифмам, векторам и математическому ожиданию. Это целевой отбор шести LLM-разборов, не случайная выборка и не экспертные эталоны. Старые KC-метки не передавались применяющему карту агенту. Подробности происхождения и условий использования — в [заметке источника](legacy-source-note.md).

## Все 12 решений о текущих шагах

Сокращения: `conditional` — `conditional_application`; `supported` — `supported_application`; `no_action` — `no_current_action`. Статусы описывают свидетельство применения, а не освоение. Значение `full` относится к одной операции карточки; она может покрывать лишь часть всего шага.

| Случай | Вариант | Повтор | Операция | Вход | p1 / p2 / p3 | Итог | Охват current |
|---|---|---|---|---|---|---|---|
| Q01, quad_D | без контекста | 1 | full | not_shown | not_shown / known / not_shown | conditional | partial |
| Q01, quad_D | без контекста | 2 | full | not_shown | known / not_shown / not_shown | conditional | partial |
| Q01, quad_D | с контекстом | 1 | full | supported | known / known / known | supported | partial |
| Q01, quad_D | с контекстом | 2 | full | supported | known / known / known | supported | partial |
| Q02, vec_dot | без контекста | 1 | none | not_shown | not_shown / not_shown / not_shown | no_action | none |
| Q02, vec_dot | без контекста | 2 | none | not_shown | not_shown / not_shown / not_shown | no_action | none |
| Q02, vec_dot | с контекстом | 1 | none | not_shown | not_shown / known / known | no_action | none |
| Q02, vec_dot | с контекстом | 2 | none | not_shown | not_shown / known / known | no_action | none |
| Q03, log_domain | без контекста | 1 | none | supported | known / known / not_shown | no_action | none |
| Q03, log_domain | без контекста | 2 | none | not_shown | not_shown / not_shown / not_shown | no_action | none |
| Q03, log_domain | с контекстом | 1 | none | supported | known / known / known | no_action | none |
| Q03, log_domain | с контекстом | 2 | none | supported | known / known / known | no_action | none |

У всех 36 оценок предусловий `checked_in_current=false`. Ни нарушенных условий, ни `violated_application` в этих входах/ответах нет; работу процедуры на таком контрасте этот опыт не проверяет. Всего восемь `no_current_action`, два условных и два подтверждённых применения.

**Q01.** В current явно получены корни через дискриминант. Без исходного уравнения применение остаётся условным; результат s3 добавляет конкретный полином, а s1 — смысловое ограничение. В обоих повторах итог меняется на supported. Выбор подходящего по смыслу корня остаётся за пределами quad_D, поэтому охват current — partial. Это ожидаемая перемена на известном случае разработки, не оценка причинной пользы для обучения.

**Q02.** Прежние координаты не добавляют явной связи суммы квадратов со скалярным произведением вектора на себя. Ортонормированность также не передана. Оба повтора в обеих ветвях сохраняют no_current_action: вычисление длины само по себе не выполняет правило свидетельства vec_dot. Это отсутствие достаточного свидетельства карточки, а не обнаруженная ошибка вычисления длины.

**Q03.** Контекст сообщает ранее найденные условия, однако current выполняет замену переменной и преобразования, используя ОДЗ. Это не новое составление ограничений логарифмов. Во всех четырёх ответах no_current_action; переноса прежнего действия в текущий шаг в этих ответах не обнаружено.

| Совпадение двух повторов | Без контекста | С контекстом |
|---|---|---|
| Наблюдаемая операция | 3/3 | 3/3 |
| Доступность входа | 2/3 | 3/3 |
| Статусы предусловий | 5/9 | 9/9 |
| Охват current | 3/3 | 3/3 |
| Итог support | 3/3 | 3/3 |

Три несовпадения оснований требуют обсуждения. В Q01 по-разному читаются действительность единственной неизвестной из ограничения q>1 и степень полинома из слова «квадратное». В Q03 один ответ оценивает структуру явно показанных логарифмов, другой — полноту всего исходного выражения. В plain r1 Q03 вход назван supported при неизвестном p3; итог no_current_action по строгому правилу от этого не меняется. Raw не исправлялись и ни один ответ не выбран как эталон. Большее согласие в state на трёх известных примерах не устанавливает общую устойчивость и не определяет границы освоения.

## Перенос на шесть готовых трасс

| Трасса | Что сопоставлено | Что карта не покрывает в показанном способе |
|---|---|---|
| L01, показательное уравнение | нет назначений | Логарифмическая запись корня, замена основания, численная оценка и округление |
| L02, числовое выражение | нет назначений | Значения логарифмов единицы/основания и вычисление степени |
| L03, разложение вектора | lin_eq: два скалярных уравнения внутри s3; vec_lincomb: проверка заданной комбинации в answer | Построение СЛАУ, метод Гаусса, организация обратной подстановки и поиск коэффициентов как целого |
| L04, линейная зависимость | нет назначений | Размерность и теорема о числе линейно независимых векторов |
| L05, ключи | нет назначений | Индикаторные величины, их ожидания и линейность ожидания |
| L06, прибыль | нет назначений | Построение прибыли, её значения по сценариям, ожидание по вероятностям |

Оба назначения L03 имеют `full`, доступный вход, все предусловия known и supported_application, но относятся к отдельным подфрагментам. В частности, вычисление заданной комбинации в проверке не означает, что карточка покрыла обратный поиск коэффициентов. Числовое сходство формул ожидания и среднего не даёт mean_freq: вероятности не являются абсолютными частотами. Также нет vec_dot только по внешнему виду суммы произведений. В raw перечислены 17 упоминаний непокрытых действий; это предложения о пробелах, не 17 новых проверенных KC и не полная разметка арифметики.

Применение выполнено один раз на всю готовую трассу. Его нельзя сравнивать как ещё одну ветвь контекстного опыта: там оценивался только current. В L03 коэффициенты для проверки поступают из более ранних действий той же трассы; два назначения не являются двумя независимыми успехами переноса. Ни отсутствующие назначения, ни пропуски карты не означают дефицит умения ученика.

## Надёжность и проверки

Офлайн [analyze.py](analyze.py) проверяет 17/17 хешей заморозки, равенство карточек/текущего шага между ветвями, порядок входов, полноту идентификаторов и предусловий, допустимые значения полей, формулу support, источники и буквальность 107/107 цитат. Проверены восемь ссылок происхождения current/предыдущих результатов с SHA-256 и JSON pointer, шесть точных извлечений учебных трасс из локального снимка и связи official_links с буквальными anchors официального входа. [Технический отчёт](derived/technical.json) сохраняет каждую проверенную цитату и хеш каждого raw; это проверка целостности и правил, не смысловой корректности.

Отдельный [captures.json](captures.json) закрепляет SHA-256 всех шести исходных JSON: карточек, четырёх применений контекста и переноса. Он создан после просмотра при завершении отчёта 28 октября, а не до генераций; позволяет обнаружить последующую порчу, но не устанавливает неизменность до этого снимка. Сохранены ссылки и SHA заданий и заявленных входов. Agent ID и точное время генераций неизвестны и отмечены null; задания не выдаются за полный журнал фактического выполнения. Анализатор проверяет 6/6 raw по captures до записи derived; несовпадение останавливает анализ.

Baseline — исторический снимок 348 файлов, более широкий, чем замороженные входы этой пробы. При первоначальном завершении анализа совпали 348/348. Последующие обновления главным агентом AGENTS.md и README этапов 28 октября должны отражаться в baseline_mismatches как `historical_document_change`, а не ошибка опыта. Другие отличия исторических файлов отмечаются отдельно для просмотра. Этот снимок не обновляется анализатором; повторное построение отчёта может изменить только его сравнение с текущим состоянием документов, не результаты замороженных применений.

Сохранённый [source-verification.json](source-verification.json) сообщает о более ранней сверке шести блоков с GitHub на фиксированном ref. Текущий анализ проверяет согласованность этой записи с локальным снимком, но не выполняет новый сетевой запрос. Полные приватные файлы не сохранены, поэтому их blob SHA нельзя заново вычислить только из этих фрагментов. Источник и права на первичные оригиналы задач по ним не установлены; публикация приватных материалов этой работой не выполнялась.

В [legacy-math-check.json](legacy-math-check.json) сохранена отдельная проверка выбранной арифметики, преобразований строк и реконструкции L03; исходный код — [check_legacy_math.py](check_legacy_math.py). Код и источник привязаны хешами. Это не внешний эталон и не полная проверка моделей: L05 условно требует равномерной перестановки, L06 трактует весь тираж как проданные экземпляры. Необычная запись `78*1` в L03 сохранена; проверка согласуется с подразумеваемой строкой для c3. Пустые source_caveats в raw/transfer.json не отменяют этих замечаний аудитора.

Проверки кода: 14 тестов с внесением дефектов в копии сохранённых ответов проверяют отказы при неверной цитате, неверном источнике, переносе контекста в действие current, пропавшем предусловии, дубликате, неверном support, изменении байта замороженного файла и ошибках checked_in_current. Отдельный тест копирует все шесть raw во временную папку внутри опыта и меняет примечание одного JSON: синтаксис остаётся валидным, но captures обнаруживает изменение. Предметных синтетических положительных примеров в этом опыте нет; тестовые копии используются только для проверки анализатора.

## Как воспроизвести

Из корня репозитория, без сети и моделей, достаточно стандартной библиотеки Python:

```powershell
.venv/Scripts/python.exe -B -X utf8 research/2026-10-27-map-context-transfer/test_analyze.py
.venv/Scripts/python.exe -B -X utf8 research/2026-10-27-map-context-transfer/analyze.py
```

Вторая команда заново записывает только `derived/technical.json`, `derived/summary.json`, `derived/evidence-registry.json`, `cards.md`, `evidence-registry.md` внутри этой папки. Проверки captures, заморозки, происхождения или цитат останавливают анализ до записи результата. Не запускайте prepare.py повторно и не пересоздавайте captures.json ради обхода несовпадения: входы и снимок raw сохраняются. README и review-notes.json — отдельный человеческий отчёт и явно записанные интерпретации; автоматический парсинг не выводит их смысл.
