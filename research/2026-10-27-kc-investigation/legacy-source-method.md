## Что именно сохранено для подсчёта

[legacy-calculus-input.json](legacy-calculus-input.json) содержит минимальную структурную выборку: все десять файлов `skills/calculus/analysis/01_…`–`10_…`, списки `task_id`/`kcs_used`, канонические ID и их `synonyms_merged` из `00_kc_catalog.md`, пути и Git blob SHA файлов calculus. Условия, ответы и решения в эту выборку не включены. Это не весь старый корпус: выводы количества относятся только к calculus. Этот раздел выбран для воспроизводимого структурного аудита, а не как предметное ограничение нашего ЕГЭ-проекта.

Для повторного получения через GitHub `fetch_file` нужны `repository_full_name`, каждый сохранённый `path` и неизменный `ref` выше. Для списка файлов использован рекурсивный Git tree; ответ не был обрезан. Git blob SHA находятся во входном JSON. Авторизация — обычный доступ пользователя к приватной репе; токены в артефактах не сохраняются.

Из текстов анализов последовательно извлекались маркеры `task_id` и inline-массивы `kcs_used`. Во всех десяти файлах число маркеров совпало с числом массивов, block-формат `kcs_used` отсутствует. Записи соединены по позиции внутри файла; составной ключ — путь файла и `task_id`, поскольку номера задач между разделами повторяются. Порядок и буквальные ID сохранены.

Использованные регулярные выражения JavaScript:

```javascript
/^\s*-\s*task_id:\s*"?([^"\n]+)"?/gm
/kcs_used:\s*\[([^\]]+)\]/g
/kcs_used:\s*\n/g
/canonical_kc_id:\s*(\w+)[\s\S]*?synonyms_merged:\s*\[([^\]]*)\]/g
```

Для массивов — разделение по запятым, удаление внешних пробелов и одинарных/двойных кавычек. Каталог содержит 44 маркера и 44 извлечённых записи. Это извлечение проверенных простых массивов в конкретной версии, не универсальный парсер YAML.

## Как считать и что числа означают

[recompute_legacy_audit.py](recompute_legacy_audit.py) работает только с сохранённым JSON:

- частота — число задач, в которых буквальный ID встречается хотя бы раз;
- повторяемый ID — минимум две задачи;
- наличие файла — совпадение имени ID с именем `.md` в дереве calculus, исключая `analysis/`;
- отдельная иллюстрация применяет ровно сохранённые алиасы каталога. Спорные соответствия не исправляются и не становятся принятыми;
- неописанные алиасами ID сохраняются; их наличие не доказывает отсутствие соответствующего умения у пользователя или в неявном справочнике.

Folder notes и overview входят в список файлов-источников, но не засчитываются как определения умений: в результате не выводится их общее число как число skill-файлов. Совпадение файла для каждого из 44 канонических ID проверено основным агентом по дереву.

Прочитанный старый `export/analyze_kc_cooccurrence.js` не запускался. Его алгоритм рассмотрен отдельно: он читает исходные списки из analysis, исключает `00_`, не применяет aliases и не проверяет смысл. Наш пересчёт не выдаётся за воспроизведение полного старого отчёта `kc_clusters.md`.

Происхождение цитат текущей ЕГЭ-репы проверяет [verify_evidence.py](verify_evidence.py). Проверка сохранности опирается на [baseline-files.json](baseline-files.json): это уже имевшиеся незакоммиченные файлы, а не снимок всего Git-репозитория. Сам хеш-манифест не восстанавливает потерянное содержимое.
