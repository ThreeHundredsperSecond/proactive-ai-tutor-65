Ты размечаешь математическую задачу для предметной модели тьютора. Реши задачу самостоятельно по условию. Не обращайся к источникам, ответам и готовым решениям. Не используй инструменты. Верни только JSON, без Markdown.

Общие определения и детализация:
Step — конкретное содержательное математическое действие с проверяемым результатом в данном решении. Выделяй смену математической операции или основания; элементарную арифметику внутри одной операции не дроби. Не добавляй шаги «прочитать условие», «записать ответ». Включи необходимые доказательства, ограничения и проверку полноты, если без них решение не обосновано. Для многопунктной задачи охвати все пункты и обозначь их в action. Не перечисляй неиспользованные альтернативы.
KC — кандидатное переиспользуемое умение, необходимое для действия: name начинается с глагола, description задаёт математическую операцию и условия применения. Не включай в KC числа, имена точек и контекст конкретной задачи. KC не равен теме, конкретному результату или целому методу. Разные формулировки одного умения объединяй внутри задачи; один KC может относиться к нескольким шагам, один шаг — к нескольким KC. Не добавляй умения, которые фактически не применены.
Method — осмысленный способ решения, объединяющий упорядоченные Step для достижения цели или отдельного пункта. Назови стратегию, а не тему и не «решение задачи». Не создавай Method для каждой элементарной операции; не объединяй независимые пункты без общего способа. step_ids отражает порядок применения.
Это кандидаты предметной модели, не доказанные предпосылки освоения и не оценка ученика.

Итоговая структура (строго эти поля):
{"task_id":"...","solution_status":"solved|partial|unsolved","steps":[{"id":"s1","action":"...","result":"...","kc_ids":["k1"]}],"kc_candidates":[{"id":"k1","name":"...","description":"..."}],"methods":[{"id":"m1","name":"...","step_ids":["s1"]}],"warnings":[]}
Используй одно из значений solution_status: solved, partial, unsolved. Все id уникальны внутри типа; ссылки должны существовать. Неиспользованных KC и пустых методов не должно быть. Полное решение находится в action/result, отдельное поле solution не добавляй. В warnings внеси конкретные сомнения, недостаточность данных или необоснованные места; если их нет, оставь []. Не выдавай догадку за доказательство.

Первый этап: только реши задачу и выдели Step. На этом этапе в steps[].kc_ids поставь [], kc_candidates и methods оставь []. Сохрани остальные поля итоговой структуры. Второй этап будет назначать KC и Method по этому результату.
