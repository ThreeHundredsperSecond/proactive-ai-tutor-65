# Воспроизводимый разбор 19 задач × 3 повтора

План зафиксирован 25 октября 2026 года до нового запуска. Основание — обсуждение с пользователем; промпт A из исследования 02.1 сохраняется без изменений. Два ранее полученных ответа остаются отдельным пилотом и не подменяют новые повторы.

## Что делаем

1. Замораживаем корпус, промпт, условия и изображения; создаём реестр 57 ожидаемых ответов.
2. Для каждого задания выполняем три разбора с независимым контекстом. Агенты не видят ответы источника, другие разборы и документы проекта.
3. Сохраняем каждый исходный ответ отдельно. Невалидные ответы и сбои сохраняем; молчаливой замены неудачных повторов нет.
4. Код проверяет JSON и связи, строит таблицы с указанием исходного файла и локального ID каждой сущности.
5. Проверяем математические рассуждения и разметку. Замечания, исправления и статусы проверки храним отдельно. Большинство ответов не является эталоном.
6. Сопоставляем KC по математической операции, объектам и условиям применения. Сохраняем каталог и явную таблицу соответствий; сомнения не скрываем автоматическим объединением по имени.
7. Ноутбук повторно строит таблицы, метрики и графики из сохранённых ответов и записей проверки. Он не запускает агентов или API.

## Что означает воспроизводимость

- **Восстановление анализа:** сохранённые входы и ответы → сохранённые решения о проверке/сопоставлении → таблицы → метрики → графики. Эти вычисления можно повторить локально без модели.
- **Повторение генерации:** другой человек может передать те же запросы и изображения агентам, но новые ответы не обязаны совпасть. Версия модели, скрытые инструкции среды и часть настроек агентного запуска не контролируются этим репозиторием. Не называем это точным API-экспериментом.
- Все изображения условия сохраняются, SVG дополнительно отрисовываются в PNG; хеши оригинала и производного файла фиксируются. Доступный текст не подменяет математическую формулу на изображении.
- Промпт A запрещает инструменты при решении. Отдельная записанная обвязка разрешает только загрузку входа до решения и сохранение готового JSON после решения. Это отличие среды явно отмечается.
- Каждый повтор начинается с пустого контекста (`fork_turns=none`). Доступные сведения о среде и исходный commit записываются; недоступные настройки не выдумываются.

## Артефакты одного запуска

В `data/annotation/runs/<run_id>/`:

| Артефакт | Откуда получается |
|---|---|
| `manifest.json`, `prompt-A.txt`, `environment.txt` | Подготовка: реестр ожидаемых повторов, версии и хеши |
| `inputs/`, `images/`, `requests/`, `jobs/` | Только условия из корпуса, их изображения, подстановка A и служебные инструкции |
| `raw/<task_id>_r<repeat>.txt` | Ответ соответствующего отдельного агента; не переписывается обработчиком |
| `reviews/` | Явные содержательные рецензии с автором, причинами и статусами |
| `catalog.json`, `kc_mapping.json` | Смысловой каталог и соответствия исходных KC общим KC |
| `derived/` | Только производные таблицы, показатели и графики; перестраиваются кодом |

Исправление разметки должно быть отдельным файлом с причиной и ссылкой на исходный ответ. До реализации поддержки исправлений анализ использует только исходные ответы с явными статусами проверки.

## Метрики и знаменатели

- Валидный JSON / 57 ожидаемых ответов; корректная структура / 57. Отсутствующие и повреждённые ответы учитываются, а не исчезают из знаменателя.
- Число Step, KC, Method на ответ; минимум, максимум и разброс между тремя повторами одной задачи.
- Математические ошибки, пропуски, проблемы детализации и ручные вмешательства — по явно сохранённым рецензиям. Отсутствие рецензии означает «не проверено», а не «верно».
- Семантический Jaccard: размер пересечения общих KC / размер объединения для каждой из трёх пар повторов задачи. Считается только при полном сопоставлении KC обоих ответов; пустое объединение не получает искусственную единицу. Показываем число доступных пар и отдельно статус математической проверки.
- Частота KC по задачам: число **разных задач**, а не ответов. Сохраняем матрицы присутствия отдельно по каждому повтору; объединение трёх повторов обозначаем как «встречался хотя бы в одном повторе», а не согласованную разметку.
- Частота по шагам — отдельный показатель. Доля единичных KC и co-occurrence считаются по выбранной и явно названной политике отбора проверенных ответов. Не смешиваем 57 ответов с 19 задачами.
- Официальное покрытие ФИПИ требует отдельной таблицы соответствий. Подпись темы сайта не выдаётся за официальный код; этот показатель не возникает автоматически.
- Альтернативные методы допускаются. Согласие повторов не доказывает правильность; порядок и co-occurrence не доказывают prerequisite.

## Как читать результат

Точка входа — ноутбук `notebooks/annotation-review.ipynb` и README конкретного запуска. Сначала видны полнота запуска и качество данных, затем задача и три исходных разбора рядом, затем рецензии и каталог, и только после них — предметные метрики. Каждый график строится из именованной таблицы с указанным отбором данных. Незавершённые этапы показываются явно, без вымышленных чисел.
