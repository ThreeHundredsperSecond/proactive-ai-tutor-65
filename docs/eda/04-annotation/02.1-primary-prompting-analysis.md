## 1. Какой вопрос решаем и что хотим получить

Для тьютора недостаточно списка тем вроде «планиметрия» или «вероятность». Нужна структура: **какое действие выполнено, какое умение для него нужно и как действия складываются в способ решения**. На её основе в будущем можно будет исследовать диагностику затруднений и подбор практики. Этот пилот проверяет только качество такого представления, не пользу обучения.

| Сущность | Значение | Пример на задаче №1 |
|---|---|---|
| Step | Конкретное содержательное действие с проверяемым результатом | Из свойства биссектрисы получить угол A = 60° |
| Кандидатный KC | Переиспользуемое математическое умение, требуемое для действия | Восстанавливать угол по его биссектрисе |
| Method | Осмысленный способ решения, объединяющий упорядоченные Step | Использовать биссектрису, затем сумму углов треугольника |

Связи: задача содержит Step; `steps[].kc_ids` назначает шагу один или несколько KC; один KC может встречаться в нескольких шагах; `methods[].step_ids` задаёт порядок шагов метода. id в этом пилоте локальны для одной разметки: одинаковое `k1` в двух файлах **не означает** одно и то же умение. Между запусками KC сопоставлялись по смыслу отдельно.

Рабочая детализация: разделять смену математической операции или основания; не дробить элементарную арифметику внутри одной операции; не создавать шаги «прочитать условие» и «записать ответ». Название KC должно описывать действие, описание — операцию и условия её применения, без чисел и имён объектов конкретной задачи. Method не должен быть просто темой или отдельным арифметическим действием внутри большого решения.

Точные условия для модели лежат в [inputs/](02.1-prompting-pilot/inputs/). Из исходной записи брались только `site_task_id` как `task_id` и `statement.text_accessibility`; служебная пометка `[рисунок]` убрана. Выбранные условия текстово достаточны. Каждый промпт имеет общую основу: роль → определения и детализация → единая JSON-структура → правила ссылок и неопределённости → инструкция конкретного варианта → условие задачи.

| Вариант | Последовательность | Отличие от общей основы |
|---|---|---|
| A | Условие → решение в Step + KC + Method | Всё в одном запросе |
| B | Условие → решение и Step → второй запрос → KC и Method | В B1 массивы KC/Method пустые; в B2 шаги сохраняются, сомнения фиксируются в warnings |
| C | Проверенный пример + условие → решение в Step + KC + Method | A дополнен одним полным примером разметки |

Точные промпты: [A](02.1-prompting-pilot/prompts/A.txt), [B1](02.1-prompting-pilot/prompts/B1.txt), [B2](02.1-prompting-pilot/prompts/B2.txt), [C](02.1-prompting-pilot/prompts/C.txt). У A/C подставляется `{task_json}`, у B2 дополнительно `{stage1_raw}`. Шаблоны зафиксированы до генерации; [исходный manifest](02.1-prompting-pilot/manifest.prefrozen.json) содержит SHA-256. В ходе сравнения шаблоны не менялись.

Пример C взят из другой задачи корпуса: позиция 6, task_id 699090. Для уравнения $\sqrt{76-2x}=8$ до тестов проверены ОДЗ, равносильность возведения в квадрат, единственный корень $x=6$ и подстановка. [Полная разметка примера](02.1-prompting-pilot/example.json) содержит четыре Step, четыре KC и один Method. Проверенный пример — часть C, а не подсказка из решения тестовой задачи.

Итоговая структура всех трёх вариантов:

```json
{
  "task_id": "идентификатор задачи",
  "solution_status": "solved",
  "steps": [
    {"id": "s1", "action": "действие", "result": "проверяемый результат", "kc_ids": ["k1"]}
  ],
  "kc_candidates": [
    {"id": "k1", "name": "умение через действие", "description": "операция и условия применения"}
  ],
  "methods": [
    {"id": "m1", "name": "способ решения", "step_ids": ["s1"]}
  ],
  "warnings": []
}
```

Допустимые статусы: `solved`, `partial`, `unsolved`. Полное решение должно находиться в `action/result`; отдельного поля `solution` нет. `warnings` отражает сомнения модели, но само по себе не доказывает наличие ошибки в условии или правильную самооценку ответа.

## 4. Последовательность эксперимента

```text
ПОДГОТОВКА
  Зафиксировать версию корпуса и выбрать пять задач.
  Извлечь очищенные условия без решений и ответов.
  Выбрать другую задачу для C и проверить её полную разметку.
  Зафиксировать общие определения, JSON и шаблоны A/B1/B2/C.

ГЕНЕРАЦИЯ
  Для каждого варианта, каждой задачи и каждого из трёх повторов:
    Создать свежий изолированный контекст gpt-6-luna.
    Передать фиксированный промпт и условие.
    Для B:
      Сохранить первый ответ с решением и Step.
      Во втором сообщении передать B2, условие и первый ответ.
    Сохранить исходный итоговый ответ без исправлений.

ПРОВЕРКА ПОСЛЕ ГЕНЕРАЦИИ
  Проверить исходный JSON и формальные ссылки.
  Независимо проверить математику, полноту и общность доказательств.
  Затем использовать сохранённое решение источника как дополнительную сверку.
  Отдельно оценить Step, KC и Method.
  Сопоставить KC по смыслу и сравнить повторы.
  Сохранить оценки, спорные случаи и ограничения; сравнить A/B/C.
```

Это описание фактически выполненного агентного пилота, не код прямого API-эксперимента. Модель читала файлы инструкций и входа и записывала ответы; служебные инструкции среды также присутствовали в её контексте. Для B первый и второй запросы находились в одном контексте соответствующего повтора; другие повторы были изолированы. Фиксация Step в B — часть дизайна: второй запрос проверяет назначение KC/Method и обозначение сомнений, а не свободное переписывание решения.

## 5. Полученные результаты и проверка

**Дизайн.** Прочитаны все пять файлов docs/eda/04-annotation/ и tasks.jsonl. Из 19 задач одного development-корпуса выбраны позиции 1, 4, 10, 14, 19 (site_task_id 699085, 699088, 699094, 699098, 699103). На вариант и задачу — три независимых свежих контекста модели gpt-6-luna, fork_turns=none. Завершены все 45 итоговых результатов: 15 A, 15 B, 15 C. Для B дополнительно сохранены 15 первых ответов; всего 60 содержательных этапов генерации. Прогоны не заменялись при плохом качестве ответа.

В генерацию передавались только task_id и текст условия. Все выбранные условия текстово самодостаточны; рисунок к №1 не нужен для извлечения дополнительных данных. Метаданные тем, источник, ответы, решения и критерии не передавались. Никаких внешних инструментов решения модель применять не должна была. Для C заранее выбран и проверен пример №6, site_task_id 699090: sqrt(76-2x)=8, ОДЗ x<=38, равносильное возведение в квадрат при неотрицательной правой части, x=6, проверка подстановкой. Пример включает 4 Step, 4 KC и 1 Method. Он не входит в тестовую пятёрку.

Шаблоны A/B1/B2/C зафиксированы до первого запуска; SHA-256 находятся в [manifest.prefrozen.json](02.1-prompting-pilot/manifest.prefrozen.json) и совпадают с текущими файлами. B — два запроса: решение и Step, затем KC/Method по точному первому ответу. Во втором запросе action/result/id/порядок Step запрещено незаметно исправлять; ошибки нужно отмечать в warnings. Фактически B2 выполнялся вторым сообщением в том же независимом контексте данного повтора. Первоначальная техническая запись о fresh context для B2 исправлена в [manifest.json](02.1-prompting-pilot/manifest.json), исходная запись сохранена.

**Что проверялось.** Автоматически: строгий разбор JSON без снятия Markdown, ключи, типы, id, ссылки Step→KC и Method→Step, отсутствие неиспользованных KC/непокрытых Step, порядок Method, неизменность Step в B. LLM-рецензентом вручную: математические переходы и доказательства, полнота пунктов, общность аргументов, детализация Step, предметность KC, соответствие KC действиям, связность Method. Это проверка одним LLM-рецензентом, не независимая экспертная аттестация. Рубрика разметки была операционализирована при проверке и не является заранее зарегистрированным внешним эталоном.

Математическая сверка включала независимые вычисления и доказательства: №1 — 66°, №4 — 0,32, №10 — массы 30/120/150 кг, №14 — нормаль (2sqrt(3),-2,-sqrt(3)) с квадратом нормы 19 и расстояние 8sqrt(57)/19. Для №19 проверены все 299 неупорядоченных положительных пар суммы 599 и минимальные семёрки по цифровым суммам на 1..230: любой меньший, чем 231, итог обязан целиком лежать в этом диапазоне. Аналитическая оценка для общей суммы цифр d>=7: все числа >=d, различия кратны 9, поэтому сумма >=7d+189>=238. Минимум 231 достигается на 6,15,24,33,42,51,60. Исходные решения прочитаны после завершения генераций; они согласуются с этими проверками, но автоматически эталоном не считались.

## 7. Ошибки разметки

 Чрезмерно объединённые Step — 18/45, в том числе все 9 ответов №19: один Step на весь пункт с несколькими действиями. Составной KC «выбор координат + уравнение плоскости» — 3/45 (все B_14). Метод расстояния без ссылки на Step, где подготовлена плоскость, — 3/45 (все B_14): ссылки формально существуют, но зависимость от общей подготовки остаётся неявной. Фрагментация Method на элементарное сложение масс — 1/45 ([A_10_1](02.1-prompting-pilot/raw/A_10_1.txt)). Непредметные названия KC из одного глагола — 1/45, пять KC в [A_14_2](02.1-prompting-pilot/raw/A_14_2.txt). Несоответствие названия и описания KC — 1/45 ([C_10_1](02.1-prompting-pilot/raw/C_10_1.txt)). Пропуск KC для реально выполненного вывода уравнения/построения сечения — 1/45 ([C_14_3](02.1-prompting-pilot/raw/C_14_3.txt)). Ошибка JSON — 1/45. Эти оценки не выводятся автоматически из правильности ответа.

Пустых учебных шагов вроде «прочитать условие» и неиспользованных KC не обнаружено. Дополнительную содержательную проверку концентрации в [C_10_2](02.1-prompting-pilot/raw/C_10_2.txt) не штрафовали как избыточную. Отдельный Method на одноступенчатую простую задачу №4 допустим: это весь способ решения, а не фрагмент многошагового решения.

## 8. Примеры



- Удачно: [C_14_1](02.1-prompting-pilot/raw/C_14_1.txt). Сначала вводятся произвольные a,h, затем отдельно находятся уравнение плоскости, полное сечение и равенство боковых сторон; только для расстояния подставляется a=h=4. Связи s1→координаты, s2→плоскость, s3→сечение, s4→равенство длин и s5→расстояние содержательны. Это наиболее аккуратный общий геометрический разбор в пилоте.
- Удачно: [A_1_1](02.1-prompting-pilot/raw/A_1_1.txt). Два проверяемых перехода: ∠A=2·30°=60° и ∠B=180°−60°−54°=66°; два переносимых KC: восстановить угол по биссектрисе и применить сумму углов треугольника. Один Method связывает s1,s2. Все девять разметок №1 семантически аналогичны.
- Неудачное решение: [A_19_1](02.1-prompting-pilot/raw/A_19_1.txt) и [A_19_2](02.1-prompting-pilot/raw/A_19_2.txt) выбирают семь чисел с наименьшей общей суммой цифр 1 и выдают 1111111. Допустимая семёрка 6,15,24,33,42,51,60 с суммой 231 опровергает минимум. В [A_19_1](02.1-prompting-pilot/raw/A_19_1.txt) есть предупреждение о пробеле, но solution_status остаётся solved.
- Неудачное решение: [C_14_3](02.1-prompting-pilot/raw/C_14_3.txt) ложно включает C1 в плоскость; подстановка даёт −4sqrt(3), а не 0. Затем объявляет условие ошибочным. Предупреждение об «опечатке» само является ошибкой модели.
- Неудачная разметка при верной математике: [A_14_2](02.1-prompting-pilot/raw/A_14_2.txt) называет KC «Задавать», «Определять», «Исследовать», «Доказывать», «Вычислять». Описания помогают восстановить смысл, но такие названия не образуют удобный переиспользуемый каталог.
- Эффект второго запроса: [B_19_2](02.1-prompting-pilot/raw/B_19_2.txt) и [B_19_3](02.1-prompting-pilot/raw/B_19_3.txt) замечают неполноту первого решения и понижают статус до partial. [B_19_1](02.1-prompting-pilot/raw/B_19_1.txt) замечает пробел в warnings, но сохраняет solved. Ошибки первых Step не устраняются по зафиксированному правилу B.

## 9. Устойчивость повторов

 KC сопоставлялись вручную по name+description и математической операции. Таблица соответствий на уровне каждого KC сохранена в [reviews.json](02.1-prompting-pilot/evaluation/reviews.json). Составные KC не разбивались задним числом на более мелкие для повышения сходства. Считался Jaccard трёх пар повторов отдельно для каждой задачи, затем среднее пяти задач. Для C_19 только два валидных исходных JSON дают одну пару; повреждённый третий ответ в основную оценку устойчивости не включён. Поэтому одинаковый вес задач не равен одинаковому числу пар для C.

| Позиция | A | B | C |
|---|---:|---:|---:|
| 1 | 1,00 | 1,00 | 1,00 |
| 4 | 1,00 | 1,00 | 1,00 |
| 10 | 0,83 | 1,00 | 0,67 |
| 14 | 0,46 | 0,53 | 0,44 |
| 19 | 0,37 | 0,35 | 0,60* |

Высокая устойчивость не означает правильность: в №19 все ответы имеют ровно 3 Step, но они слишком крупные; часть ответов воспроизводит ошибки. Сходство имён без канонизации было бы иной метрикой и не использовалось. Межзадачная повторяемость KC на столь разнородной пятёрке не оценивалась как доказательство качества каталога.

## 10. Спорные случаи

 [A_14_1](02.1-prompting-pilot/raw/A_14_1.txt) принят: текст содержит основания равенства катетов для общего случая, хотя затем лишне подставляет 4. [A_19_3](02.1-prompting-pilot/raw/A_19_3.txt) принят: нижняя оценка для d>=10 верна, но лучше явно вывести её из минимума >=19 и разрыва >=9. При максимально строгой трактовке явности этих двух доказательств счёт A снижается с 11 до 9. [C_14_1](02.1-prompting-pilot/raw/C_14_1.txt) объединяет оба пункта одним координатным Method: это принято из-за общего способа и общей подготовки. Все эти решения помечены отдельно в [reviews.json](02.1-prompting-pilot/evaluation/reviews.json), а не скрыты в итоговом числе.

## 11. Рекомендация и гипотезы

 Точный рекомендуемый исходный промпт — 02.1-prompting-pilot/prompts/A.txt; в этом пилоте он не переписывался после ответов. A даёт простую однозапросную базу, 15/15 валидных JSON и не показывает убедительного проигрыша более дорогим схемам. У B чуть выше стабильность KC, но нет преимущества по полноценным решениям и сохраняются крупные Step первого этапа. C иногда даёт более явные шаги и лучший общий разбор №14, однако один пример не дал устойчивого выигрыша и не устранил ни математические ошибки, ни сбой JSON. Улучшение будущего конвейера отдельной предметной проверкой — предложение, не протестированный здесь результат. Объяснение возможного влияния короткого радикального примера на геометрические доказательства — гипотеза, причинный эффект не установлен.

## 12. Связь с Moon et al. и наша адаптация

 Использована первичная статья Hyeongdon Moon et al., “Using Large Multimodal Models to Extract Knowledge Components for Knowledge Tracing from Multimedia Question Information”, EDM 2025: https://educationaldatamining.org/EDM2025/proceedings/2025.EDM.long-papers.170/index.html (разделы 3.2 и 3.5, Figure 5). В статье GPT-4o извлекает несколько KC с name/description из контента вопроса, затем описания группируются по embeddings; полезность проверяется через AFM/KT на данных ответов учащихся. В статье использован базовый zero-shot prompt без последующего tuning. Наша связь — открытое извлечение кандидатных KC из условия, допускающее несколько KC и последующую нормализацию. Наша адаптация — самостоятельное решение, явные Step с action/result, связи Step→KC и упорядоченные Method→Step, русские задачи ЕГЭ и сравнение A/B/C. Мы не воспроизводили clustering, AFM или KT и не проверяли освоенность/педагогическую пользу. Схема Step/KC/Method и результаты 45 прогонов не приписываются статье.

## 13. Ограничения выводов и воспроизводимости

 Это агентный пилот gpt-6-luna, не чистый эксперимент через API. Модель читала фиксированные инструкции и условие из файлов; в контексте также были служебные инструкции агента и операции чтения/сохранения. Temperature, seed, точный провайдерский snapshot, токены и стоимость не контролировались и не измерялись. Изолированы контексты, но не утверждается статистическая независимость случайных состояний сервиса. Запуски распределены блоками, не рандомизированы по времени.

Шаблоны не менялись, но отдельные агенты неточно сохранили вспомогательные копии развёрнутых промптов: 37 из 60 копий отличаются побайтно, преимущественно пробелами, JSON-форматированием и переводами строк; есть и пропуски фраз в копиях B. Эти файлы оставлены без исправления, различия сохранены в [prompt_log_audit.json](02.1-prompting-pilot/evaluation/prompt_log_audit.json). [resolved_prompts/](02.1-prompting-pilot/resolved_prompts/) содержит детерминированную точную подстановку неизменённых шаблонов и входов, не доказательство побайтного тела провайдерского API-запроса. Следовательно, строгая гарантия идентичности переданных API-запросов здесь не установлена. Это существенное ограничение, и ранжирование нужно подтвердить прямым воспроизводимым запуском с контролем тела запросов. Содержательные наблюдения относятся к полученным ответам и не выдаются за более строгий эксперимент.

Пять задач одного development-варианта, три повтора, один пример для C и один проверяющий не позволяют делать выводы по всему ЕГЭ, значимости различий или эффективности тьютора. Рекомендация A предварительная и прагматическая; разница 11/9/10 особенно чувствительна к строгости рубрики. Нет данных учеников, поэтому перенос навыков, prerequisite, mastery и польза подсказок не оценивались.


## 14. Где находятся доказательства и как продолжить

[Индекс материалов](02.1-prompting-pilot/README.md) связывает исходные ответы, точные шаблоны, восстановленные подстановки, оценки каждого результата и скрипты проверок. [Индекс 45 результатов](02.1-prompting-pilot/results-index.md) позволяет перейти к любой разметке и увидеть замечания. Исходные тексты сохранены без исправления, включая невалидный JSON. Проверочные представления и оценки лежат отдельно.

Следующий конкретный шаг — обсудить спорную детализацию и оценки с предметным экспертом, затем подтвердить сравнение прямым запуском с детерминированной сборкой и записью тела запросов и параметров. При этом сохранять все неудачные ответы, разделять ошибки решения и разметки и не выбирать промпт по одному удачному примеру. Это предложение следующего этапа; повторный строгий эксперимент ещё не выполнен.

Эта запись фиксирует пилот, а не согласование окончательного каталога KC, архитектуры тьютора или педагогической эффективности. Массовая разметка корпуса и данные учеников здесь не получены.
