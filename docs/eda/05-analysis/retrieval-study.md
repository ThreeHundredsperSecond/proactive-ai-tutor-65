# Поиск задач по сохранённой разметке

Материал включён в раздел 8.Г [единого EDA](../../../notebooks/checkpoint-2/EDA.ipynb); итог связан с разделом 9. Дата исходных модельных расчётов — 10 ноября 2026 года. Это продолжение анализа подготовленных материалов: проверяется тематический поиск, не профиль ученика и не образовательный эффект.

## Вопрос и данные

Помогают ли действия решения и локальные KC находить тематически связанные задачи по сравнению с одним условием? Из 312 включённых разборов временно исключена спорная `0B2322`; фиксированным seed 20261110 выбраны 300 из 311. Split: 20 запросов, 280 кандидатов, query seed 20261111. Полный список ID находится в `source-data/split.json` архива. Между частями не пересекаются ID задач и эвристические family-ID. Близкие по смыслу формулировки могут остаться.

Источник — сохранённый снимок банка ФИПИ и предварительные агентные разборы проекта. Путь подготовки и различия первых редакторских 50 и дополнительных серий описаны в [методологии](../04-annotation/README.md) и [протоколе расширения](../04-annotation/12-expansion-50-to-200.md). Используются действия и все локальные кандидаты KC, а не только принятые ID каталога. Это отдельный поисковый срез; он не меняет знаменатели основного EDA: 315 сохранённых задач, 312 в частотах.

## Метод

- E5: `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`; mean pooling с маской, L2, 384 координаты, `query:` / `passage:`, 512 токенов, правое обрезание.
- Reranker: `BAAI/bge-reranker-v2-m3`, ревизия `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`; без префиксов E5, все 5600 пар на вариант, лимиты 512 и 1024, `longest_first`, logit. Без дообучения; на CUDA использован float16. Результат не описывает двухэтапную схему с предварительным E5 top-k.
- Представления: условие, условие+действия, условие+названия KC, условие+названия и описания KC, полная комбинация, только названия KC. Сохранённые точные строки — `model-inputs.json`.
- Релевантность: непустое пересечение полных кодов КЭС запроса и кандидата. Они не передаются модели. Ответ, результат шага, ID, URL и аудит в модельный текст не включаются; рисунки модели не читают.
- Метрики: средние P@5, Hit@5 и обратной позиции первого релевантного среди всех 280 по всем 20 запросам. При отсутствии положительных кандидатов — нули. При равенстве оценки — порядок ID в split.
- RRF: равные веса, сумма `0.5 / (60 + ранг)`, параметры не подбирались на этих запросах.

Все сравнения исследовательские: состав вариантов уточнялся после просмотра результатов на тех же 20 запросах. Это не независимый итоговый тест выбранной конфигурации.

## Результат и значение для проекта

Компактный E5 с условием и названиями KC обеих сторон дал P@5 0.83, Hit@5 0.95, MRR 0.887500 против 0.71 / 0.85 / 0.793125 по условиям. Удаление условия, полное длинное представление и фиксированный RRF не превзошли этот вариант. Разметка кандидатов также помогла выбранному reranker. Подробные таблицы, обрезание и реальные выдачи встроены в EDA, здесь не дублируются.

Из 12 чистых дополнительных релевантных позиций E5 10 дали два близких запроса про хлеб. Для остальных 18 P@5 0.788889 → 0.811111; Hit@5 и MRR не изменились. Это анализ чувствительности после просмотра результатов. У reranker эффект распределён шире. Для одного запроса нет положительных кандидатов по КЭС, поэтому 0.95 — потолок Hit@5 данного набора.

Практическое следствие — кандидат на компактное поисковое представление рядом с полным разбором для объяснений. Готовая разметка запроса — условие двустороннего результата. Совпадение КЭС ещё не устанавливает совпадение нужного действия или полезность задачи ученику. Следующий отдельный этап — зафиксировать конфигурацию, проверить новые запросы и предметную близость найденных пар. Индивидуальная адаптация и образовательный эффект не исследованы.

## Воспроизведение без модельных прогонов

[Архив результатов](../../../notebooks/checkpoint-2/derived/retrieval-study-results.zip) хранит исходные данные и изображения, split, входы, векторы E5, матрицы оценок, ранжирования, метрики, длины, версии окружения и SHA-256. В IPYNB нет встроенного Base64-архива.

Для чтения достаточно открыть EDA: результаты уже сохранены. Для проверки выполните ячейки раздела 8.Г по порядку. Достаточно Python, NumPy, pandas, matplotlib и IPython; GPU, PyTorch, Transformers и сеть для этого раздела не требуются. Совместимый проверенный набор для повторения анализа: Python 3.12, numpy 2.0.2, pandas 2.2.3, matplotlib 3.10.0, nbformat 5.10.4, nbclient 0.10.2. Переустановка в запущенном ядре не нужна.

Из корня репозитория можно обновить только поисковый раздел, сохранив прежние выводы остальных разделов:

```powershell
python scripts/replay_checkpoint2_retrieval.py --kernel python3
```

Для полной сборки исходного EDA используется прежний `scripts/build_checkpoint2.py`. Он дополнен вызовом `add_retrieval_cells` после `update_cells`: новый раздел не потеряется при пересборке. Полная сборка требует остальных данных и зависимостей проекта; проверка поискового раздела их не требует.

Пересчёт из сохранённых оценок подтверждает арифметику и порядок выдачи. Он не повторяет инференс и не является независимой предметной проверкой разметки или близости методов.
