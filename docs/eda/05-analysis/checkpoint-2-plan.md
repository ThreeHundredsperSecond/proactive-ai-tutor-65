## Границы

Только анализ сохранённых данных и оформление. Никаких новых решений, аудитов, загрузок банка, консолидаций KC или задач 101–200. Смешанные исторические/агентные связи не дают оценки причинного эффекта метода. Отсутствуют внешний ключ всех ответов и данные учеников; не считать долю включённых задач accuracy или освоением.

Код воспроизведения: `scripts/build_checkpoint2.py`; новый анализ и журнал проверки: `notebooks/checkpoint-2/derived/`. Генератор PDF: `scripts/build_checkpoint2_pdf.py`. [Следующее исследование](data-to-tutor-protocol.md) описано отдельно и пока не запускалось.

## Воспроизведение комплекта

Из корня репозитория:

```powershell
.venv/Scripts/python.exe -B -X utf8 scripts/build_checkpoint2.py
.venv/Scripts/python.exe -B -X utf8 scripts/verify_checkpoint2.py
```

В среде Jupyter нужны nbformat, nbclient, ipykernel, matplotlib, numpy, lxml и зависимости исторического анализа (Pillow). Версии исполненной среды сохраняет `derived/verification.json`. Jupyter требует локального loopback-соединения с ядром. Отчёт пересчитывает сохранённые данные; исходные условия и raw не переписывает.

PDF собирается отдельной командой `python scripts/build_checkpoint2_pdf.py`: нужны reportlab, pypdf и шрифты Arial из `C:/Windows/Fonts`. В текущем запуске использована комплектная среда Codex с этими пакетами, без установки в проектную `.venv`. Для визуальной проверки использован Poppler: `pdftoppm -singlefile -png output/pdf/checkpoint-2-practical-value.pdf tmp/pdfs/checkpoint-2-practical-value`. PDF входит в комплект как готовый результат и не требует этих пакетов для просмотра.
