# Промпт A: 19 задач × 3 независимых повтора

Дата начала: 25 октября 2026. [План до запуска](../../../../docs/eda/04-annotation/04-agent-run-plan.md). [Ноутбук](../../../../notebooks/annotation-review.ipynb).

## Как появился результат

Сохранённый корпус `data/processed/sdamgia/90702516/tasks.jsonl` → подготовка `scripts/annotation_pipeline.py prepare` → отрисовка изображений `scripts/render_annotation_images.cjs` → отдельный агент на каждый повтор → `raw/` → `build` → `derived/*.csv` → графики и HTML из `scripts/annotation_report.py`.

Прежние два ответа не включены в новый эксперимент. Каждое из 19 условий передаётся трём агентам с отдельным контекстом; вход задачи и A одинаковы между повторами. В запросах нет ответов, решений или критериев источника.

Служебное стартовое сообщение каждого агента: «Выполни только инструкцию из файла `<абсолютный путь jobs/job_id.txt>`. Прочитай его UTF-8 через exec_command; это техническая загрузка задания. Другие документы проекта не читай. Исходный ответ сохрани в назначенный инструкцией raw-файл. В конце верни только его путь.» Точная инструкция каждого задания находится в `jobs/`. Решение выполняется без инструментов; загрузка входа и сохранение готового ответа разрешены отдельно как технические операции.

## Повторить анализ без модели

Из корня репозитория, в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r scripts/requirements-local.txt
.\.venv\Scripts\python.exe -X utf8 scripts/annotation_pipeline.py build data/annotation/runs/2026-10-25-A-19x3
.\.venv\Scripts\python.exe -X utf8 -m jupyterlab notebooks/annotation-review.ipynb
```

Выбрать ядро проекта, выполнить Run All. При другом Python можно выбрать своё ядро с установленными зависимостями. Сеть нужна только для первоначальной установки зависимостей. Фактические версии текущего запуска перечислены в `environment.txt`; файл содержит также заголовок среды и не является pip requirements. Для установки точных версий пакетов на совместимом Python 3.12 вместо диапазонов можно использовать `pip install -r data/annotation/runs/2026-10-25-A-19x3/requirements-frozen.txt`.

Ноутбук показывает полноту запуска, условие и три ответа выбранной задачи, рецензии, исходные таблицы и метрики. Он также создаёт `derived/review.html`: автономный просмотр всех задач с встроенными PNG и тремя ответами рядом. Графики лежат в `derived/*.svg`; `figures.json` указывает исходную таблицу и её хеш для каждого графика. `provenance.json` фиксирует код и источники таблиц. Модули не меняют raw, рецензии или каталог.

## Повторить подготовку и генерацию

Создать **другой** каталог запуска, например `data/annotation/runs/my-A-19x3`:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/annotation_pipeline.py prepare data/annotation/runs/my-A-19x3
```

Для получения PNG требуется Node.js и sharp версии из `scripts/annotation-image-tools/package.json` (в текущем запуске использован комплектный runtime приложения; повторный анализ готовых артефактов Node.js не требует). После установки Node.js:

```powershell
npm install --prefix scripts/annotation-image-tools
$env:SHARP_MODULE = Join-Path (Get-Location) 'scripts/annotation-image-tools/node_modules/sharp'
node scripts/render_annotation_images.cjs data/annotation/runs/my-A-19x3
```

Каждый файл `jobs/*.txt` передать **отдельному агенту с новым контекстом**. В Codex используется `fork_turns=none`, без переопределения модели. Эти вызовы организованы в чате; Python не вызывает LLM и не обещает автоматически повторить агентный запуск. Не заменять неудачный ответ молча: сохранять исходник, причину сбоя и отдельный дополнительный запуск. Параметры модели, недоступные оркестратору, обозначены как неизвестные.

## Проверка и интерпретация

Математические рецензии сохраняются отдельно в `reviews/<task_id>.json`: проверяющий, исходные хеши, статусы каждого повтора и причины. Отсутствие записи не означает успешной проверки. Общий каталог и `kc_mapping.json` — отдельные смысловые артефакты; без них семантический Jaccard и общие частоты не рассчитываются.

Смысловые решения сохранены в `catalog-part1.json`, `catalog-part2.json` и соответствующих `kc_mapping-part*.json`; основания и спорные границы — в [части 1](mapping-notes-part1.md) и [части 2](mapping-notes-part2.md). `catalog-parts.json` задаёт порядок детерминированной сборки итоговых catalog/mapping; эта сборка также выполняется в ноутбуке. Она воспроизводит сохранённые решения, не принимает новые смысловые решения автоматически.

Предметные частоты используют только ответы с математическим статусом `passed`, разметкой `accepted` и полным сопоставлением KC. Частота считается по разным задачам, с явной политикой объединения принятых повторов; это не окончательная единая разметка. Проверка LLM не заменяет внешнюю предметную экспертизу. Покрытие ФИПИ без отдельной таблицы кодов не рассчитывается.

## Статус

Получены все 57 ответов; все прошли проверку JSON и структуры. В `responses.json` зафиксированы исходные байты хешами, имена агентов и стартовые сообщения. Основной агент предварительно проверил математические переходы всех 57 ответов, явных ошибок не выявил; это не независимая экспертная валидация. Исходные ответы не исправлялись.

276 исходных KC сопоставлены с 155 черновыми кандидатами при консервативных границах определений. Доступны все 57 пар сравнений. Средний Jaccard по 19 задачам — около 0,497. **153 из 155 кандидатов встречаются только в одной задаче**: это прежде всего повод пересмотреть чрезмерно дробные определения и границы сопоставления, а не вывод об отсутствии переиспользуемых умений в ЕГЭ. Даже нулевое пересечение может возникнуть из-за различной составности KC при одинаковом математическом решении (пример: позиция 8).

Каталог не утверждён; частоты и Jaccard являются разведочными и зависят от сохранённых смысловых решений. Следующее действие — просмотреть конкретные спорные сопоставления, прежде чем интерпретировать карту навыков. Новые генерации для этого не нужны.

Проверены unit-тесты отбора и связей, контрольные суммы, ссылки документов; ноутбук выполнен сверху вниз на полном наборе. Читаемость графиков проверена по PNG.
