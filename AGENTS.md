## Структура и ведение EDA

- Три уровня: `docs/eda/README.md` — общий маршрут и сводный статус; `docs/eda/<этап>/README.md` — цель, прогресс и продолжение; отдельные файлы внутри этапа — материалы и результаты.
- После работы обновляй README соответствующего этапа: что сделано и где результат, что узнали, открытые вопросы, место остановки и следующее конкретное действие. Общий README обновляй только в части краткого статуса и навигации.
- Не дублируй подробные результаты между уровнями. Ссылка или план будущего файла не означает, что он уже создан. Не помечай этап выполненным только потому, что подготовлен план.

## Git и проверка изменений

- Перед изменениями проверь корень репозитория, текущую ветку и состояние рабочего дерева. Сохраняй чужие незакоммиченные изменения.
- Если пользователь не указал другую ветку, используй отдельную тематическую ветку. Изменение охвата до всей программы ЕГЭ ведётся в `docs/full-ege-math-scope`, созданной от `docs/project-vision`.
- Без явного поручения не вноси изменения напрямую в `main`, не сливай ветки и не включай автоматическое слияние. Не переписывай чужую историю.
- Ограничивай изменения порученной задачей. Для документации проверь diff, относительные ссылки, структуру Markdown и схемы; для кода запускай проверки, соответствующие изменению.
- Не коммить секреты, персональные данные учеников и локальные материалы без оснований для их публикации.
- В отчёте кратко укажи изменённые файлы, ветку, выполненные проверки и ограничения. Не утверждай, что push, тесты или слияние выполнены, если они не выполнены.

## Формулы в GitHub Markdown

- Для формул внутри строки используй `$...$`, для отдельной формулы — блок ```math` (с закрывающими тройными обратными кавычками). Не используй `\\(...\\)` и `\\[...\\]` в файлах GitHub Markdown.
- Не используй одиночные `$` на отдельных строках для блочных формул. Пример:

````markdown
```math
J(A,B)=\\frac{|A\\cap B|}{|A\\cup B|}
```
````

- После записи прочитай фактическое содержимое файла из GitHub и проверь точное число знаков `$`, обратных слэшей и ограждений блоков. Перед редактированием согласованного текста показывай предлагаемые изменения и меняй только одобренное.
